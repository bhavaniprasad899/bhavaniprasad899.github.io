📈 SOC Operations — Blue Team Training

Learn how Security Operations Centers work. This section covers SIEM, alert analysis, incident response, log management, and threat detection — the core skills of a SOC analyst.

1. What is a SOC?

A Security Operations Center (SOC) is a team that monitors and protects an organization's IT infrastructure 24/7. SOC analysts work in tiers:

  • Tier 1 (Triage): Monitors alerts, filters false positives, escalates real threats
  • Tier 2 (Investigation): Deep dives into escalated incidents, contains threats
  • Tier 3 (Threat Hunting): Proactively searches for hidden threats, reverse engineers malware

2. SIEM Tools (Security Information & Event Management)

SIEM collects logs from all systems and alerts on suspicious activity.

Splunk — Search & Correlation

# Basic search — find failed logins
index=windows EventCode=4625

# Search for brute force (many failed logins from same IP)
index=windows EventCode=4625 | stats count by src_ip | where count > 10

# Search for suspicious PowerShell
index=windows sourcetype="WinEventLog:Microsoft-Windows-PowerShell/Operational"

Wazuh (Open Source SIEM)

# Wazuh rule example — detect new user creation
<rule id="100001" level="10">
    <if_group>windows</if_group>
    <field name="win.eventdata.eventID">4720</field>
    <description>New user account created</description>
</rule>

3. Alert Triage — Real Scenarios

Scenario 1: Multiple Failed Logins (Brute Force)

Alert: 50 failed login attempts from IP 185.220.101.x within 2 minutes

Triage Steps:

  1. Check if the source IP is internal or external
  2. Look at the target accounts — admin accounts?
  3. Check if any login succeeded (EventCode 4624 after 4625)
  4. If external, add IP to firewall blocklist
  5. Escalate if credential compromise is confirmed

Scenario 2: Outbound Connection to Known Malicious IP

Alert: Internal host 10.0.1.55 connected to 203.0.113.5 (known C2 server)

Triage Steps:

  1. Isolate the host from the network immediately
  2. Check what process made the connection
  3. Look for recently created/modified files
  4. Capture a memory dump for analysis
  5. Check other hosts for similar connections

Scenario 3: Unauthorized Software Installation

Alert: Mimikatz detected on workstation WS-102

Triage Steps:

  1. Confirm — was it a red team exercise? If no, escalate immediately
  2. Check who was logged in at the time
  3. Look for lateral movement from this host
  4. Reset affected user credentials
  5. Begin incident response process

4. Log Analysis — What to Look For

Windows Event Logs — Key IDs

4624  — Successful logon
4625  — Failed logon
4634  — Logoff
4648  — Logon with explicit credentials
4672  — Admin logon
4688  — Process created
4698  — Scheduled task created
4720  — User account created
4732  — User added to group
7045  — Service installed

Linux Log Analysis Commands

# Check authentication logs
cat /var/log/auth.log | grep "Failed password"

# Check for sudo usage
cat /var/log/auth.log | grep "sudo"

# Check cron jobs
cat /var/log/syslog | grep CRON

# List all listening connections
netstat -tulpn

# Check running processes
ps aux --sort=-%mem

5. Incident Response (IR) Playbook

4-Phase IR Process

PHASE 1: PREPARATION
- Have playbooks ready
- Ensure logging is enabled everywhere
- Maintain updated asset inventory

PHASE 2: DETECTION & ANALYSIS
- Monitor SIEM alerts
- Validate and triage
- Determine scope of incident

PHASE 3: CONTAINMENT & ERADICATION
- Isolate affected systems
- Remove malware
- Patch vulnerabilities

PHASE 4: RECOVERY & LESSONS LEARNED
- Restore from clean backups
- Document findings
- Update security controls
